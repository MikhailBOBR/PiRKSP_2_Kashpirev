## Реализация

CSV использует UTF-8 и разделитель `;`. Поля: supplierId, supplierName, product, price, quantity. В `samples` три файла; поставщики Sever, Volna и Vector, товары SSD, монитор, ноутбук и периферия. Для денежных расчётов используется BigDecimal.

| Требование | Реализация |
|---|---|
| Проверка и создание каталога | Path, Files.exists, Files.createDirectories |
| Имя, размер, время изменения | inspect, Files.list, Files.size, Files.getLastModifiedTime |
| Поиск входных файлов | Проверка расширения .csv без учёта регистра |
| Чтение NIO | Первый CSV через FileChannel и ByteBuffer; остальные Files.readAllLines |
| Обработка | Проверка полей; исключение нулевого остатка; сумма price × quantity по поставщику |
| Контрольная сумма | Потоковое SHA-256; HexFormat |
| Архивация | Files.move в processed; уникальное имя при повторном запуске |
| Наблюдение | WatchService, ENTRY_CREATE и ENTRY_MODIFY, обработка OVERFLOW |
| Некорректные CSV | Отдельный каталог rejected с причиной ошибки |

```powershell
.\run.ps1 --demo
.\run.ps1 --seed --once
.\run.ps1 --seed
```

Режим `--demo` обрабатывает три образца, через 2 секунды добавляет четвёртый CSV и завершает наблюдение через 7 секунд. Без `--demo` WatchService работает до Ctrl+C.

Сценарий: incoming → обнаружение → чтение → валидация → агрегация → SHA-256 → processed. Демо публикует файл атомарным перемещением из `.part`; для внешнего копирования предусмотрено ожидание стабильного размера. Для большого медленного копирования надёжнее тоже использовать `.part` и переименование после окончания записи.

Проверка выполнена: сумма Sever = 63200.00, Volna = 116400.00, Vector = 265000.00; новый файл Orion даёт 24500.00. Полный фактический вывод находится в `run.log`. SHA-256 можно сверить командой `Get-FileHash data/processed/supply-01.csv -Algorithm SHA256`.

### Файловый обмен и Java NIO

Файловый обмен позволяет передавать сведения о товарах без прямого подключения к базе поставщика. Отправитель формирует файл, а получатель проверяет его структуру, рассчитывает результат и сохраняет исходный документ в архив обработки. Для такого обмена важно различать поступивший файл, успешно обработанный файл и документ с ошибочными данными: наличие файла в каталоге ещё не означает, что сведения пригодны для использования.

В Java NIO путь представлен объектом Path. Он описывает расположение файла, но сам не выполняет ввод и вывод. Класс Files предоставляет операции создания каталогов, перечисления файлов, чтения и перемещения. В SupplierExchange эти средства используются совместно: base.resolve формирует пути incoming, processed и rejected, Files.exists проверяет первоначальное состояние, а Files.createDirectories создаёт недостающие каталоги. Повторный запуск не требует предварительно удалять рабочие папки.

Использование пакета NIO не делает каждую операцию автоматически неблокирующей. Чтение обычного файла через Files.readAllLines и FileChannel в этом приложении выполняется последовательно. Это соответствует масштабу учебного обмена и делает порядок обработки воспроизводимым. Сетевые Selector и неблокирующие SocketChannel для файлового сценария не требуются.

### Канал и состояния буфера

FileChannel даёт доступ к байтам файла, а ByteBuffer хранит порцию прочитанных данных. Буфер имеет position, limit и capacity. Сразу после allocate позиция равна нулю, предел совпадает с ёмкостью. Чтение из канала увеличивает position. Вызов flip переводит буфер в режим извлечения: limit становится равен числу записанных байтов, position снова равен нулю. После получения очередной порции clear подготавливает тот же буфер к следующему чтению.

В программе используется буфер на 1024 байта. Цикл продолжается до возвращения −1, поэтому обработка не ограничена первой порцией. Полученные байты накапливаются в ByteArrayOutputStream, после чего весь результат декодируется как UTF-8. Декодирование после объединения порций позволяет не разрывать многобайтовый символ между двумя чтениями. При этом итоговый файл целиком хранится в памяти; для больших выгрузок нужен потоковый CSV-разбор.

### Контрольная сумма и события каталога

SHA-256 вычисляется по исходным байтам, а не по сумме цен или преобразованным строкам. Результат содержит 256 бит и выводится как 64 шестнадцатеричных символа. Такая сумма позволяет сопоставить обработанный документ с исходным экземпляром и выявить изменение содержимого. Она не удостоверяет личность отправителя: для этого понадобилась бы подпись или другой механизм аутентификации.

WatchService уведомляет об изменениях зарегистрированного каталога. После получения WatchKey приложение извлекает события, разрешает относительное имя через incoming.resolve и возвращает ключ в наблюдение методом reset. Событие ENTRY_CREATE может прийти до завершения копирования файла; повторные ENTRY_MODIFY также допустимы. Поэтому перед чтением выполняется проверка стабильности размера, а демонстрационный отправитель сначала пишет live.part и затем атомарно переименовывает его в CSV.

### Модель поставки и формат CSV

Формат содержит заголовок supplierId;supplierName;product;price;quantity. Разделителем выбран символ точки с запятой, кодировка — UTF-8, десятичная часть цены отделяется точкой. В отличие от полноценного CSV-парсера, split(";", −1) не поддерживает кавычки и разделители внутри названия. Для подготовленных тестовых файлов это ограничение допустимо; оно явно определяет контракт входных данных.

Проверка строки требует ровно пять полей, положительный идентификатор, непустые названия, неотрицательные цену и количество. Цена хранится как BigDecimal: это позволяет считать денежную стоимость без погрешности двоичной арифметики double. Записи с quantity = 0 корректны, но не входят в стоимость доступного товара. Итог каждого поставщика вычисляется как сумма price × quantity по его доступным позициям.

### Организация каталогов и поиск документов

Метод inspect выводит имя, размер в байтах и Files.getLastModifiedTime для всех обычных файлов. Метод csv дополнительно проверяет Files.isRegularFile и окончание имени .csv без учёта регистра. Поэтому подкаталог, файл live.part и посторонний документ не рассматриваются как входная поставка. Метод scan сортирует найденные пути, что обеспечивает одинаковый порядок первоначальной демонстрации.

Каталог samples содержит три подготовленные выгрузки. Флаг --seed копирует их в incoming, --once выполняет один проход и завершает приложение. Флаг --demo дополнительно создаёт четвёртую поставку через две секунды и наблюдает каталог семь секунд. Без --once и --demo приложение продолжает наблюдение до внешней остановки. Рабочие пути рассчитываются относительно папки запуска.

### Чтение и вычисление результатов

Первый найденный CSV проходит через readChannel, остальные читаются Files.readAllLines с явной кодировкой. Флаг channelUsed показывает выбор способа чтения, а строки Reader в протоколе подтверждают его фактическое применение. Программа проверяет заголовок до разбора записей и игнорирует пустые строки. TreeMap сохраняет итоги в порядке идентификаторов поставщиков.

Метод sha читает файл блоками по 4096 байт и обновляет MessageDigest. В process контрольная сумма и размер определяются перед перемещением документа. После успешного разбора Files.move переносит исходный файл в processed, а протокол связывает имя результата, размер, SHA-256, число доступных позиций и итоги. При совпадении имени unique добавляет префикс System.nanoTime, сохраняя ранее обработанный документ.

### Отклонение данных и наблюдение

Ошибки формата и числовых значений перехватываются как IllegalArgumentException. Документ перемещается в rejected вместе с причиной отказа в журнале. Ошибка одного такого документа не останавливает scan. Ошибки доступа к файловой системе имеют другую природу: в цикле наблюдения IOException приводит к повторной попытке, а при первоначальном проходе ошибка может завершить запуск. Это ограничение следует учитывать при использовании недоступных каталогов.

В наблюдении обрабатываются ENTRY_CREATE и ENTRY_MODIFY. При OVERFLOW вызывается повторное сканирование: даже если отдельные уведомления потеряны, оставшиеся CSV можно обнаружить по фактическому состоянию каталога. Проверка размера требует трёх одинаковых наблюдений с интервалом 100 мс и ограничена сорока попытками. Это эвристика готовности, а не доказательство завершения произвольного внешнего копирования; атомарное переименование предпочтительнее.

### Разбор результатов

Первоначальный запуск подтверждает обработку трёх независимых документов; динамический файл не заменяет один из них. Сумма 24 500 для новой поставки получена как 3500 × 7. Строка обнаружения появляется после запуска WatchService, поэтому этот фрагмент подтверждает именно автоматическое реагирование на поступление, а не очередной ручной проход по папке.

Число байтов и хэш следует сравнивать с конкретным исходным файлом: перевод строк или изменение кодировки меняют SHA-256 даже при одинаковых значениях полей. При повторном --demo префиксы имён и время изменения отличаются. Дополнительный repeat-demo.log сохраняет такой запуск отдельно, поэтому исходный run.log остаётся воспроизводимым свидетельством приведённых рисунков.

### Ограничения

Программа рассчитана на небольшие локальные UTF-8 выгрузки. Она не реализует цифровую подпись, распределённую очередь файлов и поддержку всех вариантов CSV. Для эксплуатации потребовались бы потоковый разбор, протокол готовности документа и журнал повторных попыток после перезапуска.
